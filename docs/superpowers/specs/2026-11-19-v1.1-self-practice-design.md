# v1.1 自主练习增强 设计

- 日期：2026-11-19
- 状态：待确认

## 1. 意图与背景

v1.0（阶段 0–5）已完成。v1.1 范围 = 原 4 项自主练习增强（其中「软提示分级准入」「总时长上限」按用户最新要求前置到前端、后端不再校验）+ 题型改造，叠加实现。

## 2. 目标 / 非目标 / 反目标

**目标**
- 题型改为 4 种：不定项选择、简答题、代码填空、场景题（替换现有 `choice`/`code`）。
- 换一批、总题量上限优化、练习历史。
- 移除后端时长准入校验（30–90 分钟由前端把关）。

**非目标**
- 断点续做；题库模式/随机抽题/去重（v1.2）；前端；后端时长校验。

**反目标**
- 破坏 DDD 依赖规则；破坏 `start_practice`「生成」路径行为；引入新表/迁移。

## 3. 约束

同 v1.0：Python 3.13.5、FastAPI、SQLAlchemy 2.x、Pydantic v2、统一响应 `ok(data, trace_id)`。确定性逻辑用代码，LLM 只做生成与解释。

## 4. 决策

### 4.1 题型改造（核心）

四种题型与**规范字符串**（替换现有 `choice`/`code`，`short_answer`/`scenario` 保留原名）：

| 题型 | type 字符串 | 判分方式 | 说明 |
|------|-----------|---------|------|
| 不定项选择 | `multi_choice` | 确定性 | 4 选项，正确项 1~多个；集合完全一致才得分（0/1） |
| 简答题 | `short_answer` | LLM 批改 | 不变 |
| 场景题 | `scenario` | LLM 批改 | 不变 |
| 代码填空 | `code_fill` | 确定性 | 仅当截取区间内**任一 ``` 代码块 > 10 行**时出题；挑选核心部分挖**多个空**（不覆盖整段代码） |

**各题型数据结构（LLM 生成 / 判分用）：**
- `multi_choice`：`content {stem, options:[4]}`, `reference_answer {correct:[正确选项列表]}`, 作答 `answerContent.selected:[...]`。判分 `set(selected) == set(correct)`。
- `short_answer`：不变。
- `scenario`：不变。
- `code_fill`：`content {stem, code(核心部分挖空，多处，用 ______ 占位)}`, `reference_answer {answers:[按空位顺序的被挖内容]}`, 作答 `answerContent.answers:[...]`。判分逐空位去首尾空白精确比对：`score = 正确空位数 / 总空位数`，`is_correct = 全部空位正确`。

**代码块检测**：`has_code_block(text)` 从「`"```" in text`」改为「解析 ``` 围栏块，任一代码块行数 > 10」。

**分配**：`allocate_types` 返回 `{multi_choice, short_answer, scenario, code_fill}`，逻辑不变（三必出各 ≥1 + 代码填空约 30% 封顶 4）。

**判分分派**（`exam_grading`）：`multi_choice`/`code_fill` 走确定性；`short_answer`/`scenario` 走 LLM。

**学情联动**：`learning_analytics` 的 `SUBJECTIVE_TYPES` 从 `("short_answer","scenario","code")` 改为 `("short_answer","scenario")`。

### 4.2 时长校验前置到前端

学生选完视频后，总时长是否在 30–90 分钟内由**前端**提示，后端 `start_practice` **不再校验时长**。因此：
- 删除 `contexts/self_practice/domain/admission.py` 的 `check_admission` 及其在 `service.start_practice` 中的调用。
- `StartPracticeRequest` 不再需要 `confirm` 标志（无软提示档）。

### 4.3 换一批

`StartPracticeRequest` 加 `regenerate: bool = False`。`true` 时跳过旧题复用，对全部选中视频重新生成。

### 4.4 总题量上限优化

修 `merge_counts`：保证任何情况下 `sum(结果) ≤ cap`。当 `n * floor > cap` 时，保底下限退化为 `cap // n`（floor 尽力而为，主约束是总量 ≤ 30）。

### 4.5 练习历史

新增 `GET /api/v1/practice/history?studentId={studentId}` → `{sessions:[...]}`（按 `started_at` 倒序，`{practiceId, startedAt, status, totalScore, questionCount}`）。

`submit_practice` 成功后回填 `PracticeSession`：`status="submitted"`、`submitted_at=now`、`total_score=本次总分`。

## 5. 影响面

- `contexts/exam_paper_generation/`：`anchor.has_code_block`、`allocation.allocate_types`、`infrastructure/adapter.py` 的 `_SCHEMAS`/prompt。
- `contexts/exam_grading/`：`domain/grading.py`（`grade_choice` → 多选集合判分 + 代码填空精确判分）、`infrastructure/adapter.py`（分派）。
- `contexts/self_practice/`：`domain/admission.py`（删除）、`domain/merge.py`、`domain/ports.py`（题型注释）、`application/service.py`（去准入、加 regenerate/历史）、`infrastructure/repository.py`、`interface/schemas.py`、`interface/routes.py`。
- `contexts/learning_analytics/application/service.py`：`SUBJECTIVE_TYPES`。
- 相应测试：`test_generation_rules.py`、`test_grading.py`、`test_grading_adapter.py`、`test_generation_adapter.py`、`test_domain.py`、`test_service.py`、`test_practice_api.py`。

## 6. 留给实施者的自由度

- 题型字符串精确取值（已定 `multi_choice`/`code_fill`）、`_SCHEMAS` 的 JSON 细节、代码填空占位符（`______`）。
- `practice/history` 是否加 `limit` 参数（默认返回全部或最近 N 条）。
- `admission`/`sessions` 响应字段命名（以测试为准）。

## 7. 已确认项

- 题型：不定项选择（集合完全一致计分）、简答、场景、代码填空（核心部分挖多个空、不覆盖整段代码、逐空位精确比对按空位计分；任一代码块 > 10 行触发）。
- 代码填空分配约 30%（封顶 4）。
- 时长 30–90 分钟由前端校验，后端不判断（移除 v1.0 准入校验）。
- 换一批、总题量上限优化、练习历史照做。
- 叠加实现（G）。
