# 学生分组项目实施方案（7–10 天 · 含前端与云部署）

> 面向把「码帮智 · 教育智能体平台」作为分组实践作业的教学场景。
> 本文档是**规划文档**，只描述如何组织学生完成项目，不含任何实现代码。

## 0. 项目定位与边界

- **教师当前代码 = 参考答案**：只用于课堂演示和业务讲解，**不直接给学生**。
- **学生可参考「架构」**：文件夹结构、目录命名、分层方式、端口契约、依赖规则（即架构文档 + 目录骨架的形态），不提供具体业务实现代码。
- **学生从零写实现**：拿到需求/设计/架构文档后，在组长新建的空白仓库里自行实现全部后端业务代码与前端代码。
- **交付基线**：后端可运行 + 前端可交互 + 测试通过 + 上线到阿里云 ECS 可公网访问 + 文档齐全。
- **周期**：按 **10 天**设计，含一个 **7 天「本地可演示」检查点**（见 §7）。

### 技术栈（已确定）

| 层 | 选型 |
|----|------|
| 后端 | Python + FastAPI + SQLAlchemy 2.x + Pydantic v2 + Alembic + pytest + import-linter |
| 架构 | DDD 限界上下文 + Ports & Adapters（六边形），`interface → application → domain ← infrastructure` |
| 前端 | Vue 3 + Vite + Element Plus + Pinia + Vue Router + Axios + ECharts |
| 数据库 | 开发 SQLite（零配置）→ 上线 MySQL 8（SQLAlchemy 配置切换 + Alembic 迁移） |
| 部署 | 阿里云 ECS + Docker Compose（后端 + MySQL + Nginx），HTTPS 可选 |

## 2. 角色与职责

### 组长（1 人）

1. **建仓与权限**：GitHub/Gitee 建仓，邀请组员，设置分支保护与 PR 规范。
2. **公共部分创建**：`api/`、`shared/`、`orchestrator/` 骨架与实现；**前端工程骨架**（Vite 工程、路由、布局、Axios 封装、公共组件、1 个示范页）。
3. **契约定义（两大契约，Day 1 冻结）**：
   - **端口契约**：`QuestionGenerationPort` / `GradingPort` 签名（见 §5）。
   - **API 契约**：统一响应 `ok()`、路由前缀 `/api/v1/...`、错误码、**每个前端页面对应的请求/响应 JSON 示例**。
4. **任务分配与进度跟进**：拆分任务、建看板、每日例会、更新里程碑。
5. **协调与集成**：解决跨组员接口/依赖冲突，合并分支，跑全量测试。
6. **部署统筹**：Dockerfile / docker-compose、ECS 环境、Nginx、MySQL、上线。

### 组员（4–5 人）

1. 认领 1–2 个后端领域，按分层用 TDD 实现，并端到端兼做自己领域对应的前端页面。
2. 遵守公共 API 约束与端口契约。
3. 编写对应单测 + 领域 README。
4. 每日例会汇报进度、暴露阻塞。

## 3. 交付物清单

### 公共部分（组长负责）

| 目录 | 职责 | 关键内容 |
|------|------|----------|
| `api/` | 薄 REST 入口 | `main.py`（FastAPI 实例）、`handlers.py`（异常/响应处理）、`routes/`（health + 各领域路由聚合） |
| `shared/` | 共享基础设施 | `infrastructure/llm`（LLMPort + FakeLLMAdapter + 工厂）、`db`（base/session/models，**DB URL 可配置**）、`memory`（MemoryPort + in_memory）、`web/response`（统一 `ok()`）、`observability`、`tool_registry`、`common/`（util/exception） |
| `orchestrator/` | 全局编排层（轻量占位） | 占位目录，预留跨领域编排；真正的「练习编排」在 `self_practice` 应用层 |

### 后端领域（共 7 个）

| 领域 | 层数 | 是否暴露 API | 核心职责 |
|------|------|--------------|----------|
| `sales_assistant` | 四层 | 是 | 营销/客服：意图识别、课程推荐、FAQ、留资 |
| `teaching_assistant` | 四层 | 是 | 答疑 RAG：课件切块、向量检索、带溯源回答、转人工 |
| `course_assistant` | 四层 | 是 | 课程/学习路径规划、督学触达 |
| `learning_analytics` | 四层 | 是 | 学情分析（画像、掌握度趋势、薄弱点归因） |
| `self_practice` | 四层 | 是 | 自主练习编排者：准入、出题编排、判分、历史 |
| `exam_paper_generation` | 二层 | 否 | 出题生产者：锚点截取、题量/题型分配、LLM 出题 |
| `exam_grading` | 二层 | 否 | 批改生产者：选择/代码填空确定性判分、主观题 LLM 批改 |

> 五个标准上下文四层齐全；`exam_paper_generation` / `exam_grading` 为**生产者**，只有 `domain + infrastructure` 两层、不暴露 REST API。

### 前端（Vue 3，中等范围）

| 页面 | 对接 API | 说明 |
|------|----------|------|
| 对话页（营销/答疑） | `POST /api/v1/sales/chat`、`POST /api/v1/teaching/ask` | 统一聊天 UI，标签切换营销/答疑，展示回复 + 溯源 |
| 课程路径页 | `POST /api/v1/course/plan`、`POST /api/v1/course/plan/refresh` | 选方向/岗位 → 展示学习路径，可刷新重排 |
| 自主练习页 | `GET /api/v1/practice/available-videos`、`POST /api/v1/practice/start`、`POST /api/v1/practice/submit`、`GET /api/v1/practice/history`、`GET /api/v1/practice/{practiceId}` | 选视频发起练习 → 逐题作答 → 提交判分 → 看结果/历史 |
| 学情看板页 | `GET /api/v1/analytics/student/{studentId}` | 画像卡片 + 掌握度趋势（ECharts 折线）+ 薄弱点列表 |

> 加分项（时间够再做）：后台管理（课程/题目/线索 CRUD）。
> 前端「端到端」分工：组长搭骨架，各领域负责人兼做对应页面（详见 §6）。

## 5. 关键协作点：端口契约（后端内部，消费者驱动）

全项目**最容易出错**的跨成员协作点。

- `self_practice` 在自己的 `domain/ports.py` **定义**：`QuestionGenerationPort`（`plan_counts` / `generate_by_video`）、`GradingPort`（`grade`）。
- `exam_paper_generation` / `exam_grading` **实现**这两个端口，并从 `self_practice.domain.ports` 导入 `Question` / `GradeResult` 类型。
- 依赖方向单向：生产者可依赖 `self_practice.domain.ports`，但**禁止**依赖其它叶子上下文（`practice-producers-one-way` 契约）。

**依赖规则（import-linter 强制）：**

1. `shared` 被隔离（不依赖任何上下文）。
2. 叶子上下文（sales/teaching/course/analytics）互相独立、只依赖 `shared`。
3. 生产者（exam_paper_generation/exam_grading）→ 只依赖 `shared` + `self_practice.domain.ports`。

**冻结时机：Day 1 下午前冻结端口签名**（含 `Question` / `GradeResult` 字段），改契约需组长同意并同步双方。

## 6. 任务分配（两套方案，含前端）

> 分配原则（已确定）：**组长不领领域**，只负责公共部分 + 部署/集成/统筹；**每名组员领 1 个领域**，人数少的组部分组员领 2 个领域。端口契约（`self_practice` 定义、出题/批改实现）固定拆给「组员 1 + 组员 2」协作，是明确的跨人协调点。

### 7 个后端领域分配

| 成员 | 5 人组（组长 1 + 组员 4） | 6 人组（组长 1 + 组员 5） |
|------|---------------------------|---------------------------|
| 组长 | 公共 `api`/`shared`/`orchestrator` + 部署/集成/统筹 | 同左 |
| 组员 1 | `self_practice`（编排者，定义端口） | `self_practice`（定义端口） |
| 组员 2 | `exam_paper_generation` + `exam_grading`（生产者，实现端口） | `exam_paper_generation` + `exam_grading`（实现端口） |
| 组员 3 | `sales_assistant` + `teaching_assistant` | `sales_assistant` |
| 组员 4 | `course_assistant` + `learning_analytics` | `teaching_assistant` |
| 组员 5 | — | `course_assistant` + `learning_analytics` |

> - **5 人组**：组员 2/3/4 各领 2 个领域，组员 1 领 1 个（`self_practice` 是最大编排者）。
> - **6 人组**：组员 2 领 2 个（两个薄生产者）、组员 5 领 2 个，其余各 1 个。
> - 出题/批改两个生产者常被分到一起（都薄、都实现同一端口），`self_practice` 单独一人（最重）。

### 前端分配（已确定：端到端）

前端由**组长搭骨架**（Vite 工程、路由、布局、Axios 封装、公共组件、1 个示范页），**各领域负责人端到端兼做自己领域对应的前端页面**：

| 前端页面 | 负责组员 |
|----------|----------|
| 对话页（营销/答疑） | sales / teaching 负责人 |
| 课程路径页 | course 负责人 |
| 自主练习页 | self_practice 负责人 |
| 学情看板页 | learning_analytics 负责人 |

> 出题/批改两个生产者无独立前端页；对话页由营销、答疑两位负责人按「营销 / 答疑」标签分块协作。

## 9. 测试规范

- **方法**：TDD（先写失败测试 → 最小实现 → 重构），每个函数/方法都有对应测试。
- **后端分层测试**：
  - `domain` 纯函数（判定/映射/切块/准入）—— 纯逻辑单测。
  - `application` service —— 编排测试（注入 Fake 端口/假仓储）。
  - `infrastructure` adapter —— 用 `FakeLLMAdapter` 替代真实 LLM 测试。
  - `interface` —— API 冒烟/错误处理测试。
- **全量命令**：项目根目录 `pytest`（Windows 参考 `.venv/Scripts/python.exe -m pytest`）。
- **覆盖率目标**：后端 ≥ 80%。
- **依赖校验**：`lint-imports`（import-linter）保证依赖方向合规。
- **前端测试**（加分项）：关键交互用 Vitest + Vue Test Utils 冒烟；时间紧则靠人工走查。

## 10. 部署方案（阿里云 ECS）

### 开发态（全程）

- SQLite 零配置；`uvicorn api.main:app --reload` 启动后端；前端 `npm run dev`。
- `shared/db/session.py` 用环境变量控制 DB URL，默认 SQLite。

### 上线态（Day 8–9）

**服务器准备（组长）：**
1. 阿里云 ECS（Ubuntu 22.04 / CentOS 均可），安全组开放 `80` / `443`（`22` 仅限组长）。
2. 安装 Docker + Docker Compose + Nginx（或 Nginx 跑在容器内）。

**容器化（`docker-compose.yml`）：**
- `backend`：FastAPI + uvicorn（多 worker 可选）。
- `mysql`：MySQL 8，数据卷持久化。
- `nginx`：托管前端 `dist` 静态文件 + `location /api` 反代到 `backend`。

**切库（SQLite → MySQL）：**
1. 环境变量把 DB URL 切到 `mysql+pymysql://...`。
2. `alembic upgrade head` 在 MySQL 上建表。
3. 开发期种子数据（课程/路径/视频）用脚本或 `alembic` 种子导入。

**HTTPS（可选加分）：** `certbot` + Let's Encrypt 签发证书，Nginx 配置 443。

**上线自测清单：**
- 公网域名/IP 可访问前端首页；`/api/v1/...` 返回正常 JSON。
- 端到端走通：营销会话 → 答疑 → 课程路径 → 自主练习（出题→判分）→ 学情看板。
