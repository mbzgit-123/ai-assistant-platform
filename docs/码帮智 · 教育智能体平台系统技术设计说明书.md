## 2. 项目背景

### 2.1 背景摘要

教培业务在"售前获客—课程匹配—学习规划—课后答疑—过程督学—自主练习—学情分析"全链路中存在人力成本高、响应慢、不精准、难溯源等痛点。本项目以多智能体架构，将上述环节转化为可自动化、可追溯、可个性化的 AI 服务链路。

### 2.2 技术背景与约束

- 课程体系为编程课，课件为 PDF（大章节一文档），章节下含多个教学视频（MP4）。
- **课程管理（课程分类树、课程、章节、视频、课件 PDF）已由其他系统实现**，本系统通过对方提供的数据同步/接口获取课程结构，不重复建设。
- **用户（学生/教师/角色权限）与学习进度数据亦由已有系统管理**，本系统通过同步获取。
- 本系统为**后端 AI 智能体中台**，不提供前端界面，由已有系统/前端调用本系统 API。
- 答疑 RAG 仅基于课件 Markdown，不做视频语音转写（ASR）。

### 2.3 技术目标

1. 以应用层 Service + 端口承载各业务上下文的智能体编排，以 LangChain 统一 LLM 客户端。
2. 以 MySQL 承载业务数据与同步缓存，以 Milvus 承载课件向量化检索。
3. 以"确定性代码兜底 LLM 输出"保证出题、判分、统计的可靠性。
4. 模块化单体起步，遵循 DDD 依赖规则，支持后续拆分微服务。

## 3. 系统总体设计

### 3.1 系统定位

本系统是面向编程课教育场景的**多智能体 AI 中台**，以模块化单体形态部署，对外暴露 HTTP API 供已有系统/前端调用。系统按 DDD 限界上下文划分业务领域，每个业务领域由一个智能体承载，共享基础设施层通过 Ports & Adapters 实现依赖倒置。

### 3.2 设计原则

| 原则 | 说明 |
|------|------|
| 上下文隔离 | 业务领域独立建模，上下文之间不共享业务模型 |
| 依赖倒置 | 领域层定义端口（Port），基础设施层实现（Adapter） |
| 确定性兜底 | 出题截取、题量计算、判分统计用确定性代码，LLM 只做生成与解释 |
| 契约通信 | Agent 之间用结构化 JSON Schema 契约通信，不用自然语言交接 |
| 工具隔离 | 每个 Agent 的工具按上下文隔离，不建全局工具大杂烩 |
| 模块化单体 | 单进程内按目录组织、接口隔离，负载需要时再拆微服务 |

### 3.3 业务上下文与智能体

| 上下文 | 智能体 | 职责 | 优先级 |
|--------|--------|------|--------|
| 智能营销 | 营销 Agent | 内容投放、线索获取、转化话术 | 高 |
| 智能助教 | 助教 Agent | 答疑、引导式教学、日常互动 | 高 |
| 智能出题 | 出题 Agent | 组卷、按知识点/视频出题、课件结构化 | 高 |
| 智能评价 | 评价 Agent | 自动批改、Rubric 评分、考试诊断、评价报告 | 高 |
| 学情分析 | 学情分析 Agent | 长期学习画像、掌握度趋势、薄弱点归因 | 高 |
| 自主练习 | 自主练习 Agent | 练习会话管理、按视频触发出题、合并多视频题目 | 高 |
| 智能课程 | 课程 Agent | 课程推荐、学习路径规划 | 低 |

### 3.4 上下文关系

```
           营销 Agent          助教 Agent
                   \             /
                    \           /
        —— 共享基础设施层（LLM/记忆/可观测性/向量/工具注册）——
                    /      |      \
       出题 Agent —— 自主练习 Agent —— 批改 Agent —— 学情分析 Agent
```

- 上下文之间通过端口 + 领域事件交互，禁止直接依赖彼此领域模型。
- 学情分析为下游消费者，通过端口订阅练习、批改、答疑等事件。
- 自主练习是编排者：调用出题 Agent 生成题目，调用批改 Agent 批改，结果回流学情分析。

### 3.5 分层结构与依赖规则

```
ai-assistant-platform/
├── shared/
│   ├── common/                      # 零依赖工具
│   │   ├── util/                    # StringUtil, JsonUtil, DateUtil
│   │   └── exception/               # 统一异常体系
│   └── infrastructure/              # 纯技术能力
│       ├── llm/                     # LangChain LLM 客户端封装
│       ├── embeddings.py            # BGE-M3 Embedding 工厂（create_embeddings，跨上下文复用）
│       ├── memory/                  # 会话记忆存储
│       ├── db/                      # SQLAlchemy 会话、连接池
│       ├── messaging/               # Redis/Celery、领域事件
│       ├── observability/           # 日志、追踪、token 统计
│       └── tool_registry/           # 工具注册基础设施
├── contexts/
│   ├── sales_assistant/             # 营销/智能客服
│   ├── teaching_assistant/          # 助教（答疑）
│   ├── course_assistant/            # 课程推荐/路径规划（低优先级）
│   ├── exam_paper_generation/       # 出题
│   ├── self_practice/               # 自主练习
│   ├── exam_grading/                # 批改
│   └── learning_analytics/          # 学情分析
├── orchestrator/                    # 意图路由层，不承载业务逻辑（预留，本次交付不实现）
└── api/                             # FastAPI 路由层（对外 API）
```

**依赖方向**（严格单向）：

```
contexts/* → shared/infrastructure → shared/common
```

- context 之间禁止互相依赖，跨上下文通过端口 + ACL 交互。
- shared/common 零外部依赖；shared/infrastructure 可依赖技术栈，不得依赖任何 context。
- 用 ArchUnit（或 Python 对应的 import-linter）守住上述规则。

### 3.6 共享基础设施准入标准

放入 shared 的组件必须同时满足：**无业务语义、真实多方使用、接口稳定**。带业务语义的共用物（用户信息查询、金额计算规则等）不得放 shared，应通过端口/ACL/Shared Kernel 处理。

### 4.3 应用层 Service 编排模式

每个 Agent 的编排逻辑放在 `application/service.py`：Service 是纯编排层，按顺序调用领域纯函数（确定性）与 `LLMPort`（生成），通过领域层定义的端口注入外部依赖，实现依赖倒置。通用模式：

```python
# contexts/<ctx>/application/service.py
class SomeAgentService:
    def __init__(self, llm: LLMPort, repo: SomePort):  # 依赖注入
        self._llm = llm
        self._repo = repo

    def handle(self, req: SomeRequest) -> SomeResult:
        intent = recognize_intent(req.text)            # 确定性
        if intent.needs_clarify:
            return self._clarify(intent)
        course = self._repo.get_courses(intent)        # 端口调用
        reply = self._llm.chat(build_prompt(course))   # LLM 生成
        return SomeResult(intent=intent, course=course, reply=reply)
```

**应用场景对照**：

| Agent | Service 编排步骤 |
|-------|----------------|
| 营销 Agent | 意图识别 → 多轮追问澄清 → 课程查询 → 话术生成 → 留资 |
| 助教 Agent | RAG 检索 → 溯源定位 → 生成回答 → 会话记录落库 |
| 出题 Agent | 视频内容直读 → 题量计算 → 并行出题 → JSON 校验 → 入库 |
| 自主练习 Agent | 编排者：准入校验 → 调出题 → 合并题目 → 提交调批改 |
| 批改 Agent | rubric 确定性校验 + LLM 评分解释 |
| 学情分析 Agent | 统计聚合 + LLM 归因解释 |

### 4.4 LangChain 职责边界

LangChain 仅用于**统一 LLM 访问**，不承载业务编排（编排交给应用层 Service）：

- LLM 客户端：`ChatOpenAI`（兼容 DeepSeek/通义 OpenAI 兼容端点）或 `ChatTongyi`/`ChatDeepSeek`；
- Embedding：`HuggingFaceEmbeddings`（BAAI/bge-m3，本地 float16 + 归一化），工厂见 `shared/infrastructure/embeddings.py`；
- 工具抽象：`@tool` 装饰器，按上下文注册；
- 检索：`langchain-milvus` 封装 Milvus（混合检索：dense IP + sparse BM25），各上下文自有 `MilvusKnowledgeBase` 适配器。

### 4.5 关键组件说明

#### 4.5.1 LLM 客户端封装（shared/infrastructure/llm）

- 统一封装多模型路由，按场景选择模型：
  - 生成类（出题、话术、评分解释）：DeepSeek-chat / Qwen-max；
  - 轻量类（意图识别、题型判断）：DeepSeek-chat / Qwen-plus（低配）；
  - 推理类（学情归因）：可切换 Qwen-max / DeepSeek-reasoner。
- 统一重试、超时、降级、token 计量。

#### 4.5.2 向量化与检索封装（shared 工厂 + 各上下文适配器）

- `shared/infrastructure/embeddings.py`：`create_embeddings()` 统一返回 BGE-M3 嵌入器，供各上下文复用（避免跨上下文 import）。
- 各上下文自有 `infrastructure/knowledge_base.py`：`MilvusKnowledgeBase` 负责 Milvus 连接、Collection 管理、写入/检索，`search()` 返回 `RetrievedChunk`（含 document_name / chapter / heading_path / score）。

#### 4.5.3 事件与任务（shared/infrastructure/messaging）

- Redis 作为 Celery broker；Celery 任务：`generate_questions`、`grade_subjective`、`supervise_scan`；
- 领域事件总线：练习完成、批改完成、答疑完成等事件，供学情分析订阅。

## 5. 系统模块设计

### 5.1 Orchestrator（意图路由层）

> **预留**：本层为未来阶段的意图路由设计，**本次分组交付不实现**；当前各上下文独立暴露 REST API，直接调用。

**职责**：接收上游请求，识别业务类型并路由到对应上下文，不承载业务逻辑。

**设计**：基于请求类型（显式入口参数）+ 轻量意图识别，路由到对应上下文。路由结果返回统一响应结构。

### 5.2 营销 Agent（sales_assistant）

**职责**：售前课程咨询、课程分类引导、课程推荐、线索留资。

**能力分解**：

| 功能 | 实现方式 |
|------|----------|
| FR-001 课程分类引导 | 应用层 Service 多轮对话 + 实时调用已有课程系统 getAllSubject 获取三级分类树（进程缓存） |
| FR-002 课程介绍咨询 | 选定二级分类后实时调用 getFrontCourseList（subjectId + subjectParentId）查询课程 → LLM 组织话术 |
| FR-003 报名就业咨询 | 知识库检索（FAQ）+ LLM 生成 |
| FR-004 学习咨询 | 知识库检索（FAQ）+ LLM 生成 |
| FR-005 线索留资 | 确定性写入 lead 表 + 调用已有系统 VIP 报到接口 |

**工具**（上下文隔离）：`get_subject_tree`、`get_courses`、`save_lead`、`report_vip`。

**确定性/LLM 分工**：分类树解析、分类匹配、课程查询为确定性；意图识别与话术生成为 LLM；无匹配课程时确定性规则强制"如实告知 + 引导留资"。

### 5.3 助教 Agent（teaching_assistant）

**职责**：课后答疑、知识点讲解、课件溯源。

**能力分解**：

| 功能 | 实现方式 |
|------|----------|
| FR-008 答疑 | 问题向量化 → Milvus 检索课件分块 → LLM 基于检索结果生成回答 |
| FR-009 会话记录 | 每次答疑落库问答（user/assistant 两条，带 conversationId 归组 + 溯源 sources） |
| 溯源定位 | 检索结果携带 chapterId + 标题层级 + 段落位置，随回答返回 |

**工具**：`search_course_content`（Milvus 检索）。

### 5.4 出题 Agent（exam_paper_generation）

**职责**：按视频/知识点出题、组卷、视频内容直读。

**能力分解**：

| 功能 | 实现方式 |
|------|----------|
| FR-012 视频内容直读 | 直接读取前端传入的 courseDocument（视频内容），超 2000 字按段落二次切分或先摘要 |
| FR-013 题型定义 | 选择/简答/场景必出；代码题由区间内是否存在 ``` 代码块自动判断 |
| FR-014 题量映射 | 确定性映射表（<5 分钟 3–5；5–15 分钟 5–8；15–30 分钟 8–12；>30 分钟 10–15，封顶 15） |
| FR-015 题型分配 | 有代码块时代码题约 30%（上限 4），其余选择:简答:场景 ≈ 4:3:2 |
| FR-017 题目复用 | 同一 videoId 首次生成后入库复用，打乱顺序 |

**出题流程**（应用层 Service）：

```
读视频内容 → 计算题量与题型分配 → 逐题并行调 LLM 生成(JSON) → JSON 校验(重试一次) → 批量入库
```

**工具**：`get_video_content`、`save_questions`。

**确定性/LLM 分工**：内容读取、题量、分配为确定性代码；题目内容生成为 LLM；LLM 输出非 JSON 重试一次，仍失败则丢弃并记日志。

### 5.5 自主练习 Agent（self_practice）

**职责**：练习会话管理、准入校验、按视频触发出题、合并多视频题目（编排者）。

**能力分解**：

| 功能 | 实现方式 |
|------|----------|
| FR-010 已学视频展示 | 确定性查询 StudentVideoProgress（completedAt 非空） |
| FR-011 时长准入 | 确定性校验：累计 ≥60 分钟放行，30–60 软提示，<30 硬拦截 |
| FR-016 多视频合并 | 总题量上限 30，超出按比例缩减，每视频保底 3 道 |
| FR-018 练习归属 | 生成 practiceId，题目按 videoId 归属挂接 |
| FR-019 提交判分 | 选择题确定性判分；主观题/代码题投递批改 Agent，回填 |

**流程**：见第 8 章核心业务流程。

### 5.6 批改 Agent（exam_grading）

**职责**：逐题批改、Rubric 评分、反馈。

**能力分解**：

| 功能 | 实现方式 |
|------|----------|
| 选择题判分 | 确定性比对答案 |
| 主观题批改 | rubric 确定性校验（要点命中）+ LLM 评分与反馈生成 |
| 代码题批改 | 规则校验（语法/关键逻辑）+ LLM 解释 |

**工具**：`grade_choice`（确定性）、`grade_subjective`（LLM+rubric）、`grade_code`。

### 5.7 学情分析 Agent（learning_analytics）

**职责**：长期画像、掌握度趋势、薄弱点归因。

**能力分解**：统计聚合（确定性 SQL/聚合）+ LLM 归因解释。基于练习作答与学习进度实时计算画像、掌握度趋势、薄弱点，结果以领域对象返回，不落库。

### 5.8 课程 Agent（course_assistant，低优先级）

**职责**：课程推荐、学习路径规划（FR-006/FR-007）。基于"岗位→课程路径"知识库 + 前置依赖规则生成学习顺序，LLM 解释。v1.0 可裁剪。

## 8. 核心业务流程

### 8.1 售前咨询流程（营销 Agent）

```
用户输入咨询文本
  → 步骤1：意图识别（LLM，输出 intent + 一级/二级分类）
  → 条件路由：
      分类未明 → 引导选一级分类（实时拉取 getAllSubject 分类树，进程缓存）
      已选一级、二级未明 → 引导选二级分类
      课程介绍 → 步骤2：实时调用 getFrontCourseList（二级 id + 一级父 id）查询课程
      报名就业/学习咨询 → 步骤3：FAQ 检索 → 生成答复
  → 步骤4：LLM 组织推荐话术（只介绍课程名与核心内容，不展示课时/价格）
  → 无匹配课程 → 确定性规则：如实告知 + 引导留资
  → 步骤5：留资写入 lead + 挂接 VIP 报到
  → 返回（一级/二级分类、课程推荐、答复、留资结果）
```

### 8.2 答疑 RAG 流程（助教 Agent）

```
用户提交问题
  → 问题向量化（Embedding）
  → Milvus 检索 Top-K 课件分块（带 heading_path/source_ref）
  → 置信度判断：
      高于阈值 → LLM 基于检索分块生成讲解 + 溯源定位
      低于阈值 → 返回固定「无法回答」文案（不调 LLM，不编造）
  → 会话记录落库（user 问题 + assistant 回答两条，conversationId 归组）
  → 返回（知识点讲解 + 课件定位 + conversationId）
```

### 8.3 自主练习主流程（自主练习 Agent + 出题 + 批改）

```
学生进入自主练习
  → 查询该章节已学完视频列表（completedAt 非空）
  → 学生勾选一个或多个视频
  → 准入校验：累计时长 ≥ 60 分钟？
       否 → 返回已选时长与差额（<30 硬拦截 / 30–60 软提示）
       是 → 生成 practiceId
  → 对每个视频（并行，Celery/异步）：
       查 videoId 已有题目？
         有 → 复用，打乱顺序
         无 → 读视频内容 → 计算题量/题型分配 → 并行调 LLM 出题(JSON) → 校验 → 批量入库
  → 合并多视频题目为一套题（上限 30，按比例缩减，每视频保底 3）
  → 按视频分组返回题目
  → 学生逐题作答并提交
  → 选择题确定性判分；主观题/代码题投递批改 Agent
  → 回填 practice_answer（isCorrect/score/feedback）
  → 返回本次练习结果（对错、参考答案、解析、批改反馈、汇总）
  → 发布领域事件 → 学情分析订阅更新
```

### 8.4 督学流程（定时任务）

```
Celery Beat 定时触发 supervise_scan
  → 扫描学习进度，识别异常（长时间不学习 / 进度停滞）
  → 命中规则 → 调用已有系统短信/微信通道发送提醒
  → 记录触达日志
```

### 8.5 离线准备流程（课件与视频）

```
课件 PDF 批量转 Markdown → 存 chapter.content_md
视频上传 → ffprobe 获取 duration_seconds → 写 video
教研复制视频讲解内容 → 写 video.content_md
课件内容切块 → 向量化写 Milvus teaching_assistant_chunks（build_chunks.py → chunks.jsonl → build_knowledge_base.py）
```

## 9. 安全设计

### 9.1 认证与授权

| 场景 | 方案 |
|------|------|
| 对外 API | JWT（含角色声明）或 API Key，按角色控制接口访问 |
| 同步接口 | 内部密钥（HMAC 签名 + 时间戳防重放） |
| 角色权限 | 游客→咨询；学员→学习/答疑/练习；教师→出题/批改/学情/视频内容复制；管理员→配置监控 |

### 9.2 数据安全

- 传输层：全链路 HTTPS/TLS。
- 存储：敏感字段（联系方式）加密存储；数据库访问最小权限。
- 密钥管理：使用云 KMS 或环境变量注入，禁止硬编码。
- 数据隔离：按 studentId/tenant 隔离，查询强制带归属条件。

### 9.3 Prompt 注入与输出安全

- 用户输入与系统提示词隔离，系统指令置于更高优先级；
- 对 LLM 输出做结构化校验（JSON Schema），不合规拒绝/重试；
- 输出过滤：禁止泄露密钥、Token、内部配置、系统日志、其他学生数据；
- 出题/答疑强制"无依据不编造"，由确定性规则兜底。

### 9.4 审计与合规

- 关键操作（留资、判分、答疑会话记录、同步）记录审计日志；
- 对话与作答数据保留策略遵循隐私合规要求。

## 10. 性能设计

### 10.1 性能目标

| 指标 | 目标 |
|------|------|
| 普通 API 响应（非 LLM 生成） | P95 < 200ms |
| 答疑检索 | P95 < 500ms（不含 LLM 生成） |
| 单视频出题 | 并行出题，整体受模型耗时主导，单视频失败不阻塞 |
| 题目复用命中 | 直接查库返回，无模型调用 |

### 10.2 优化策略

| 策略 | 说明 |
|------|------|
| 题目复用 | 同一 videoId 缓存题目，避免重复调用模型（降成本） |
| 多视频并行出题 | Celery 异步并行，单视频超时隔离 |
| 模型分级 | 生成用强模型、意图/题型判断用轻模型 |
| 连接池 | SQLAlchemy 连接池 + Redis 连接池复用 |
| Milvus 索引 | HNSW 索引 + 合理分块，检索低延迟 |
| 缓存 | 课程分类树、FAQ 热点数据入 Redis |
| 异步化 | 批改、向量化、学情聚合走 Celery，接口快速返回 |

### 10.3 容量与扩展

- 无状态 API 节点可水平扩容；
- Celery worker 按队列类型（出题/批改/学情）独立扩容；
- Milvus 集群按数据量分片扩展。

## 11. 异常处理

### 11.1 异常处理原则

- 统一异常体系（shared/common/exception），映射为统一错误码与用户可理解提示；
- 隐藏内部错误细节，禁止向用户暴露堆栈与内部配置；
- 关键异常记录日志并携带 traceId。

### 11.2 异常场景处理清单

| 场景 | 处理 |
|------|------|
| LLM 服务不可用 | 重试一次，失败返回降级结果并提示 |
| 视频内容缺失 | 该视频不出题，提示教研补录内容 |
| 视频内容超长 | 按段落二次切分或先摘要 |
| 选中视频无代码块 | 静默跳过代码题，不提示 |
| 某视频出题失败 | 其他视频正常返回，失败视频提示重试或补题 |
| 累计时长不足 60 分钟 | 拦截并返回已选时长与差额 |
| 学生未学完视频 | 不出现在可选列表 |
| LLM 输出非 JSON | 重试一次，仍失败丢弃该题并记日志 |
| 批改异常 | 标记异常转人工，不阻塞其他题 |
| 数据库/向量库故障 | 快速失败 + 熔断，返回可理解提示 |
| 同步接口超时/失败 | 幂等重试，记录同步失败日志 |

## 12. 日志设计

### 12.1 日志规范

- 采用 structlog 结构化日志，字段统一包含：`timestamp`、`level`、`traceId`、`service`、`context`、`studentId`、`message`。
- 日志级别：DEBUG（开发）、INFO（关键流程）、WARN（降级/重试）、ERROR（异常）。

### 12.2 关键日志点

| 场景 | 日志内容 |
|------|----------|
| 接口访问 | 请求路径、耗时、traceId、返回码 |
| LLM 调用 | 模型、prompt 长度、token 消耗、耗时、重试次数 |
| 出题 | videoId、题量、题型分配、失败原因（JSON 校验失败等） |
| 批改 | questionId、判分结果、异常转人工标记 |
| RAG 检索 | 查询向量耗时、命中条数、置信度 |
| 数据同步 | 同步类型、条数、成功/失败 |
| 督学触达 | 学生、命中规则、触达通道、结果 |

### 12.3 可观测性

- 集成 OpenTelemetry，链路追踪贯穿 API → 应用层 Service → LLM/DB/向量调用；
- token 统计汇总用于成本核算；
- 指标（Prometheus）：请求量、错误率、P95 延迟、队列积压、LLM 调用量与成本。

## 13. 部署方案

### 13.1 部署形态

初期采用**模块化单体**：单个应用进程（FastAPI + 应用层 Service）+ 独立 Celery worker + 中间件。

### 13.2 部署架构（公有云）

| 组件 | 部署方式 |
|------|----------|
| API 应用 | 容器（Docker），云上 ECS/ACK，无状态多副本 |
| Celery worker | 容器，按队列分组（出题/批改/学情/督学） |
| Celery Beat | 单实例（督学定时任务） |
| MySQL | 云上托管 RDS（主备 + 只读副本） |
| Redis | 云上托管 Redis（缓存 + broker） |
| Milvus | Milvus 集群或 Zilliz Cloud 托管 |
| LLM/Embedding | 通义/DeepSeek API 或自建 Embedding 服务 |
| 日志/监控 | 云日志服务 + Prometheus/Grafana |

## 14. 测试方案

### 14.1 测试分层

| 层级 | 工具 | 覆盖 |
|------|------|------|
| 单元测试 | pytest | 确定性逻辑：内容读取、题量映射、题型分配、判分、准入校验 |
| 集成测试 | pytest + Testcontainers | DB/Redis/Milvus 交互、数据同步幂等 |
| 接口测试 | pytest + httpx | 对外 API 契约、鉴权、异常码 |
| Agent 评测 | 自建评测集 + 评分 | 意图识别准确率、出题 JSON 合法性、答疑溯源准确率 |
| RAG 评测 | 检索命中率、溯源定位准确率 | Milvus 检索质量 |
| 性能测试 | locust | 并发、P95 延迟、队列吞吐 |

### 14.2 关键测试点

- **出题正确性**：题量与题型分配符合规则；视频内容读取正确；代码题自动判断正确。
- **判分正确性**：选择题确定性判分；主观题 rubric 校验。
- **复用**：同一 videoId 二次发起不重复调用模型。
- **异常兜底**：视频内容缺失提示补录、LLM 非 JSON 重试、批改异常转人工。
- **数据一致性**：出题成功批量插入、提交批量插入作答。

## 15. 风险与扩展

### 15.1 技术风险

| 风险 | 影响 | 应对 |
|------|------|------|
| LLM 输出不稳定（出题质量、JSON 格式） | 题目质量与流程可靠性 | 确定性规则兜底 + JSON Schema 校验 + 重试 + 人工复核入口 |
| 国产 LLM API 限流/波动 | 高峰出题失败 | 分级模型、重试降级、队列削峰 |
| 课件 Markdown 转写质量差 | 检索不准 | 转写规范、视频内容复制规范 |
| 数据同步不一致 | 课程/进度数据滞后 | 幂等同步、增量同步、同步失败告警 |
| 上下文间耦合 | 影响拆分微服务 | ArchUnit 守依赖规则、端口 + ACL 隔离 |
| 向量检索质量不足 | 答疑不准确 | 分块策略调优、Embedding 选型、评测迭代 |

### 15.2 成本风险

| 风险 | 应对 |
|------|------|
| LLM 调用成本高 | 题目复用、代码题按需生成、模型分级、token 统计监控 |
| Milvus/中间件资源 | 云托管按量计费，容量评估 |

### 15.3 扩展规划

| 阶段 | 扩展内容 |
|------|----------|
| v1.1 | 换一批、总题量上限优化、练习历史、软提示分级准入、学情分析接入 |
| v1.2 | 题库模式、随机抽题、题目去重、考试评价独立/并入学情 |
| v2.0 | 按负载拆微服务、家校沟通、教研题库运营等第二梯队 Agent |

### 15.4 架构扩展预留

- 上下文目录独立，端口抽象已预留，拆分微服务时仅改变调用方式（进程内 → RPC/消息）。
- 事件总线已预留，学情分析等下游消费者可平滑接入 Kafka 等中间件。
- Embedding/LLM 通过 shared/infrastructure 适配器封装，可无痛切换供应商或本地化。

## 附录 A. 技术决策记录（ADR）

| 编号 | 决策 | 理由 |
|------|------|------|
| ADR-01 | 模块化单体起步 | 需求明确，避免过早拆分，按负载演进 |
| ADR-02 | 应用层 Service 编排 + LangChain 抽象 | 编排与模型能力分离，边界清晰 |

| ADR-04 | 售前课程分类/课程列表实时调用已有系统接口 | 分类树轻量（进程内缓存一次），课程列表按需实时查询，保证售前数据新鲜；课件/进度/用户等仍走同步缓存 |
| ADR-05 | 答疑 RAG 仅用课件 Markdown | 需求确认，不做视频 ASR，降低成本 |
| ADR-06 | 确定性代码兜底 LLM | 保证出题、判分、统计可靠 |
| ADR-07 | Celery 承载异步与定时 | 并行出题、批改、督学定时统一调度 |
| ADR-08 | Embedding 用 BGE-M3（本地）+ Milvus 混合检索（dense IP + sparse BM25） | 中文语义检索效果好，检索阈值经实测校准（SCORE_THRESHOLD=0.55） |
