## 3. 项目概述

### 3.1 项目背景

#### **3.1.1 业务现状与痛点**

当前教培业务过程中存在以下痛点：

1.  **售前咨询人力成本高、响应不及时，潜在学员流失**
    教培行业售前咨询量大、重复性问题多（课程方向、价格、报名流程、是否包就业等），人工客服难以
    7×24 小时覆盖，夜间/高峰时段响应慢，游客和潜在学员容易流失。

2.  **用户意向模糊、课程体系复杂，难以精准匹配课程**
    学员常以“想学编程”这类模糊表达咨询，而平台课程分类树庞大、方向与岗位对应关系复杂，人工匹配效率低且不专业，容易出现推荐偏差或过度营销。

3.  **课后答疑依赖人工、响应慢，且答案难以溯源到课件**
    学员学习中的问题量大且碎片化，授课老师无法即时响应；普通问答工具回答缺乏依据、无法定位到原始课件位置，学员难以对照学习，未解决问题也缺乏转交机制。

综上，需要建设智能体平台，用 Agent
把教培行业“售前获客—课程匹配—课后答疑”三个环节中依赖人工、响应慢、不精准、难溯源的痛点，转化为可自动化、可追溯、可个性化的
AI 服务链路。

#### 3.1.2 业务背景

-   课程体系为**编程课**，课件以 PDF
    形式存在（大章节一文档），每个章节对应多个教学视频（MP4）。
-   视频按课件讲解，但非逐字照读，存在口语解释与自由发挥。
-   学生按视频学习，需要边学边练；教师/教研需要出题、组卷、批改与学情分析。
-   平台同时服务销售、教学、教务等多类业务场景。

### 3.2 项目定位

**码帮智 ·
教育智能体平台**是面向编程课教育场景的多智能体系统，基于领域驱动设计（DDD）的限界上下文思想划分业务领域，每个业务领域由独立的智能体（Agent）承载，共享基础设施层通过
Ports & Adapters 实现依赖倒置。

系统主要用于：

-   信息查询（课程咨询、答疑）；
-   辅助决策（课程推荐、学情分析）；
-   自动处理（出题、判分）；
-   提升业务效率（7×24 服务、降低人工成本、主动流失预警）。

系统不用于：

-   替代人工决策；
-   执行业务审批；
-   承担专业责任（不编造课程与答案）。

## 4. 项目目标

### 4.1 总体目标

建设一个能够覆盖“售前获客—课程匹配—课后答疑—自主练习—学情分析”全链路、由多智能体承载、以确定性规则兜底
LLM 输出的智能化教育平台。

### 4.2 具体目标

|      |                                                         |
|------|---------------------------------------------------------|
| 编号 | 目标                                                    |
| G-01 | 支持游客/潜在学员完成 7×24 小时在线课程咨询与线索留资   |
| G-02 | 提供精准的课程推荐能力                                  |
| G-03 | 提供基于课件/视频的答疑与知识点溯源能力                 |
| G-04 | 提供按视频粒度的自主练习、自动出题与自动批改能力        |
| G-06 | 提供学情分析能力（长期画像、掌握度趋势、薄弱点归因）    |
| G-07 | 降低售前咨询人力成本，提升响应及时性与线索转化率        |
| G-08 | 以确定性规则兜底 LLM 输出，保证出题、判分、统计的可靠性 |
| G-09 | 提供后台管理系统，支撑课程/题目/线索运营、知识库运维与系统监控   |

### 4.3 设计目标

-   业务领域独立建模，上下文之间通过端口与事件交互，不共享业务模型。
-   共享基础设施层仅承载纯技术能力，避免成为耦合中心。
-   每个上下文可由一个智能体或一组协作子智能体承载，支持独立演进。
-   出题、批改等场景中 LLM 输出不可靠时，以确定性规则兜底。

## 6. 系统范围

### 6.1 系统包含范围

系统支持以下业务上下文（各由一个智能体承载）：

|            |                |                                                           |            |
|------------|----------------|-----------------------------------------------------------|------------|
| **上下文** | **智能体**     | **职责**                                                  | **优先级** |
| 智能营销   | 营销 Agent     | 内容投放、线索获取、转化话术                              | 高         |
| 智能助教   | 助教 Agent     | 答疑、引导式教学、日常互动                                | 高         |
| 智能出题   | 出题 Agent     | 组卷、按知识点/视频出题、课件结构化                       | 高         |
| 智能评价   | 评价 Agent     | 自动批改、Rubric\[**评分量规**\] 评分、考试诊断、评价报告 | 高         |
| 学情分析   | 学情分析 Agent | 长期学习画像、掌握度趋势、薄弱点归因                      | 高         |
| 自主练习   | 自主练习 Agent | 练习会话管理、按视频触发出题、合并多视频题目              | 高         |

### 6.2 系统不包含范围

当前版本不包含：

-   家校沟通、教研题库运营等第二梯队 Agent；
-   按负载拆分微服务（初期为模块化单体）；
-   独立考试评价上下文（视变更节奏待定）。

后续作为独立需求评估。

### 6.3 上下文关系

                 营销 Agent          助教 Agent  
                         \               /
                          \             /
                —— 共享基础设施层（LLM/记忆/可观测性/工具注册）——
                          /      |      \
                 出题 Agent —— 自主练习 Agent —— 批改 Agent —— 学情分析 Agent

-   上下文之间通过端口 + 领域事件交互，禁止直接依赖彼此领域模型。
-   学情分析为下游消费者，通过端口订阅练习、批改、答疑等事件，不反向依赖。
-   自主练习是编排者：调用出题 Agent 生成题目，调用批改 Agent
    批改，结果回流学情分析。

### 6.4 上下文判定原则

新业务是否独立成上下文，看三点：**业务语言是否不同、规则约束是否不同、变更节奏与消费者是否不同**。仅功能不同而规则同源的，应作为已有上下文的子模块。

### 6.5 架构约束

#### 6.5.1 分层结构

    ai-assistant-platform/
    ├── shared/                          # 跨上下文共享，严格限定纯技术
    │   ├── common/                      # 零依赖工具
    │   │   ├── util/                    # StringUtil, JsonUtil, DateUtil
    │   │   └── exception/
    │   └── infrastructure/              # 技术能力
    │       ├── llm/                     # LLM 客户端封装
    │       ├── memory/                  # 会话记忆存储
    │       ├── observability/           # 日志、追踪、token 统计
    │       └── tool-registry/           # 工具注册基础设施
    ├── contexts/                        # 按业务领域隔离
    │   ├── sales_assistant/
    │   ├── teaching_assistant/
    │   ├── exam_paper_generation/       # 出题
    │   ├── self_practice/               # 自主练习
    │   ├── exam_grading/                # 批改
    │   └── learning_analytics/          # 学情分析
    └── orchestrator/                    # 意图路由层，不承载业务逻辑（预留，本次交付不实现）

#### 6.5.2 依赖规则

-   依赖方向严格单向：contexts/\* → shared/infrastructure →
    shared/common。
-   context 之间禁止互相依赖，跨上下文通过端口 + ACL 交互。
-   shared/common 零外部依赖；shared/infrastructure
    可依赖技术栈，不得依赖任何 context。
-   用 ArchUnit 或模块依赖检查守住上述规则。

#### 6.5.3 共享基础设施准入标准

放入 shared
的东西必须同时满足：**无业务语义、真实多方使用、接口稳定**。带业务语义的共用物（如用户信息查询、金额计算规则）不得放
shared，应通过端口/ACL/Shared Kernel/独立上下文处理。

#### 6.5.4 部署形态

初期采用**模块化单体**：单进程内按上述目录组织，通过接口隔离。某个上下文（如营销）负载或团队规模需要独立部署时再拆微服务。

## 7. 用户使用场景

### 7.1 场景名称：售前课程咨询

#### 7.1.1 场景描述

用户希望：以“想学编程”等模糊表达了解课程方向、价格、报名流程，并获得匹配的课程推荐。

#### 7.1.2 输入

用户输入：咨询文本（可能模糊，如“想学编程”）。

#### 7.1.3 系统处理

系统：

1.  分析输入，判断咨询意图（分类引导 / 课程介绍 / 报名就业 /
    学习咨询）；
2.  多轮对话引导用户逐级选择课程分类（一级分类 → 二级分类）；
3.  选定二级分类后，实时调用已有课程系统接口查询该分类下课程；
4.  经大模型组织生成推荐话术；
5.  咨询中记录留资并挂接 VIP 报到流程。
6.  记录本次会话（用户问题与系统回答落库）。

#### 7.1.4 输出

返回：识别出的一级/二级分类、课程推荐（课程名、时长、封面、简介）、答复内容、留资记录结果、会话记录结果。

### 7.3 场景名称：课后答疑

#### 7.3.1 场景描述

用户希望：学习过程中获得即时答疑，并能定位答案对应的原始课件位置。

#### 7.3.2 输入

用户输入：学习问题。

#### 7.3.3 系统处理

系统：

1.  基于课程视频/课件进行 RAG 检索；
2.  讲解知识点并溯源定位到原始课件位置；
3.  记录答疑会话（问题与回答落库）。

#### 7.3.4 输出

返回：知识点讲解 + 课件定位。

### 7.4 场景名称：自主练习

#### 7.4.1 场景描述

用户希望：按已学视频发起练习，巩固知识，并自动获得判分与反馈。

#### 7.4.2 输入

用户输入：勾选一个或多个已学完的视频。

#### 7.4.3 系统处理

系统：

1.  展示该章节下已学完的视频列表（含时长、标题）；
2.  校验累计时长 ≥ 60 分钟（&lt;30 分钟硬拦截，30–60 分钟软提示，≥60
    分钟放行）；
3.  生成
    practiceId，按视频并行出题（有题复用打乱，无题按视频内容直读出题）；
4.  合并多视频题目为一套题，按视频分组展示；
5.  学生作答后选择题自动判分，主观题调批改 Agent，回填作答记录。

#### 7.4.4 输出

返回：一套按视频分组的题目及本次练习结果（对错、参考答案、解析、批改反馈、汇总）。

## 8. 功能需求

### 8.1 智能客服模块（咨询助手 Agent）

面向游客与潜在学员，7×24 在线提供课程咨询与线索收集。

#### 8.1.1 FR-001 课程分类引导

-   **功能描述**：客服 Agent 通过多轮对话引导用户选择课程分类：先选一级分类（人工智能 / 前端开发 / 后端开发 / 数据库开发），再选该一级分类下的二级分类；用户不确定时可引导直接找老师咨询。
-   **输入**：咨询文本（可能模糊，如”想学编程”）。
-   **输出**：识别出的一级分类与二级分类。
-   **业务规则**：分类树来自已有课程系统接口（getAllSubject），实时获取并缓存；对模糊意向主动追问澄清；多轮对话中记住已选择的一级/二级分类。

#### 8.1.2 FR-002 课程介绍咨询

-   **功能描述**：用户选定二级分类后，实时调用已有课程系统接口（getFrontCourseList，携带二级分类 id 与一级分类 id）查询课程列表，经大模型组织生成课程推荐话术。
-   **输入**：一级分类、二级分类。
-   **输出**：课程推荐（课程名、时长、封面、简介）。
-   **业务规则**：课程列表实时查询；无匹配课程时如实告知（不编造），并引导留资；话术只介绍课程名称与核心内容，不展示课时与价格，不假设用户学习路径。

#### 8.1.3 FR-003 报名与就业咨询

-   **功能描述**：回答报名/入学流程、是否包就业等咨询。
-   **输入**：咨询问题。
-   **输出**：答复内容。

#### 8.1.4 FR-004 学习咨询

-   **功能描述**：回答学习类常见问题（如是否可自学、学习周期等）。
-   **输入**：咨询问题。
-   **输出**：答复内容。

#### 8.1.5 FR-005 线索留资与跟进

-   **功能描述**：咨询过程中记录用户留资（电话/微信/意向方向），形成线索并支持后续跟进。
-   **输入**：联系方式、意向方向、备注。
-   **输出**：留资记录结果。
-   **业务规则**：留资可挂接现有 VIP 报到流程。

#### 8.1.6 FR-006 会话记录

-   **功能描述**：记录客服 Agent 与用户的每次对话（用户问题与系统回答），形成可查询的会话历史，用于观察用户咨询热点、针对性优化回复话术与 FAQ 答案。
-   **输入**：用户消息、系统回答、会话 id（前端生成）、意向方向/岗位（可选上下文）。
-   **输出**：会话记录落库结果。
-   **业务规则**：每次对话落用户问题与系统回答两条记录（role 区分 user/assistant）；会话面向游客，以「打开一次会话窗口」为一次会话——conversationId 由前端在打开窗口时生成，同一窗口内所有消息共用该 ID，关闭窗口再打开视为新会话（新 ID）；会话记录与助教答疑会话统一存储、按来源区分。

### 8.2 智能助教模块

面向已购课学员与 VIP 学员，提供答疑。

#### 8.2.1 FR-008 答疑助教

-   **功能描述**：基于课程视频/课件进行知识问答，讲解知识点并溯源定位到原始课件位置。
-   **输入**：学习问题。
-   **输出**：知识点讲解 + 课件定位。
-   **业务规则**：基于课程视频/课件 RAG
    检索回答。

#### 8.2.2 FR-009 会话记录管理

-   **功能描述**：答疑过程中记录每次对话的用户问题与系统回答，形成可按会话、按学员查询的历史记录。
-   **输入**：学员问题、系统回答、溯源、会话 id（前端生成）、学员 id。
-   **输出**：会话记录落库结果。
-   **业务规则**：每次答疑落两条记录（role 区分 user/assistant）；assistant 记录携带溯源 sources；conversationId 由前端在每次打开智能助教时创建，同一次对话内多轮共用该 ID；以学员 id 标识记录归属；会话记录与客服会话统一存储、按来源区分。

### 8.3 自主练习模块

#### 8.3.1 背景与目标

学生选择已购课程后，勾选课程下若干知识点（视频），系统基于课件文档自动生成一套练习并判分，帮助学生巩固知识。出题上下文来源于所选视频自带的内容（前端通过 courseDocument 字段传入，内容源为教研预置的视频 contentMd），保证权威性与上下文可控。练习结果持久化，支撑判分与学情分析闭环。

#### 8.3.2 FR-010 课程与知识点展示

前端展示学生已购课程列表；选择课程后展示该课程下的知识点（视频）列表（含标题、时长、视频内容），支持区间选择。

#### 8.3.3 FR-011 时长校验

学生选择知识点时，前端按所选视频累计时长即时校验，要求落在 45–120 分钟之间；后端不重复校验。

#### 8.3.4 FR-012 视频内容直读出题

前端提交所选视频内容（courseDocument 字段承载视频内容，videos 仅含 videoId）。后端直接读取 courseDocument、清洗 Markdown 后作为出题上下文，调用出题 Agent 生成题目，不再依赖整篇文档与锚点截取。

#### 8.3.5 FR-013 题型定义

固定四种题型：不定项选择（正确选项数未知）、论述题（简答）、代码填空、场景分析题；前端分别渲染为 indefinite / essay / code / scenario。

#### 8.3.6 FR-014 题量映射

题量按切片内容总长度映射：&lt;1500 字 → 10 道不定项 + 3 道论述；1500–4000 字 → 12 + 4；&gt;4000 字 → 15 + 5。

#### 8.3.7 FR-015 题型分配

场景分析题固定 1 道；代码填空题固定 1 道（仅当切片区间内任一 \`\`\` 代码块 ≥15 行时才出，否则静默跳过）。

#### 8.3.8 FR-016 内容合并

多视频内容合并为一份出题上下文，题量按合并后总长度计算（见 FR-014），无单视频保底限制。

#### 8.3.9 FR-017 出题策略

每次发起练习均重新生成题目，不复用历史题目。

#### 8.3.10 FR-018 练习归属

一次练习共用一个 practiceId，题目挂到该 practiceId。

#### 8.3.11 FR-019 自动判分与批改

前端提交自然作答：不定项选择为选中下标数组、代码填空为答案数组、论述/场景为字符串。后端转换为内部判分格式后，不定项选择/代码填空走确定性判分，论述/场景题调批改 Agent 回填 isCorrect、score、feedback。

#### 8.3.12 FR-020 结果展示

提交后返回本次得分（totalScore）、满分（fullScore）与逐题结果（对错、得分、批改反馈、参考答案/解析）。

#### 8.3.13 FR-021 练习历史回顾

学生可查看历史练习记录列表（按时间倒序，仅展示已提交练习），点击进入回顾页查看成绩（答对 X/N）与逐题作答、正确答案、解析、AI 点评。

#### 8.3.14 出题 Prompt 约束

-   **不定项选择**：4 选项、正确项 1 个或多个、干扰项基于常见误区、输出 JSON。
-   **论述题**：考察概念理解，参考答案要点 3–5 条，输出 JSON。
-   **场景分析题**：构造含角色/目标/约束的具体场景，给出参考解题思路，输出
    JSON。
-   **代码填空**：只考察代码逻辑理解，按编号挖空 `___(N)___`，输出 JSON。
-   概念类题型 prompt 注明“忽略代码块，只基于文字讲解出题”。
-   课程内容可能存在 OCR/转写错别字，prompt 注明“按正确语义理解并纠正错字，
    不照搬错字进题干/选项/参考答案”。

#### 8.3.15 视频内容复制规范

-   教研标注时，将每个视频讲解对应的课件文档片段整体复制到该视频的
    contentMd 字段（保留 Markdown 标题与代码块）。
-   只复制该视频实际讲解的内容，跳过过渡语与收尾语。
-   先复制一个章节的 10 个视频跑通闭环，验证后再批量复制。

### 8.4 学情分析模块（学习分析 Agent）

面向已购课学员，基于练习作答记录与视频学习进度，聚合生成学习画像、分章节掌握度趋势与薄弱点归因，辅助学生查漏补缺、教师精准辅导。作为练习闭环的下游消费者，核心统计用确定性代码计算，薄弱点归因解释用 LLM 生成。

#### 8.4.1 背景与目标

学情分析消费自主练习的作答记录（批改结果回流）与视频学习进度，输出三类结果：学习画像（整体概览）、掌握度趋势（分章节正确率随时间变化）、薄弱点（低正确率章节归因）。数据来源为练习作答记录与视频进度，不反向依赖其它上下文。

#### 8.4.2 FR-022 学习画像

-   **功能描述**：聚合学生已购课程数、已完成/总视频数、整体正确率、主观题平均分、最近活跃时间，形成学习画像。
-   **输入**：学生 ID。
-   **输出**：画像（已购课程数、已完成视频数、总视频数、整体正确率、主观题平均分、最近活跃时间）。
-   **业务规则**：整体正确率 = 已判分作答中答对数 / 已判分作答数；主观题平均分仅统计论述/场景题已评分项；最近活跃时间取「最近完成视频时间」与「最近作答时间」的较晚者；无数据时相关字段置空。

#### 8.4.3 FR-023 掌握度趋势

-   **功能描述**：按章节 × 日期聚合正确率，输出分章节掌握度趋势序列，供前端折线图展示。
-   **输入**：学生 ID。
-   **输出**：趋势点列表（章节 ID、周期日期、正确率）。
-   **业务规则**：仅统计有章节归属且已判分的作答；按日期排序。

#### 8.4.4 FR-024 薄弱点归因

-   **功能描述**：识别正确率低于阈值的章节作为薄弱点，并由 LLM 生成一句话归因与改进建议。
-   **输入**：学生 ID。
-   **输出**：薄弱点列表（章节 ID、章节标题、正确率、归因建议），最多 3 个。
-   **业务规则**：正确率阈值 60%；按正确率升序取前 3；LLM 归因失败时用确定性兜底话术（如「章节「X」正确率 Y%，建议回看对应视频并加强练习」）。

### 8.5 智能体设计

#### 8.5.1 通用设计原则

-   一个上下文对应一个主 Agent，内部可按任务拆子 Agent，由主 Agent
    调度。
-   Agent 之间用结构化 schema（如 JSON
    Schema）契约通信，不用自然语言交接。
-   Agent
    只做自然语言入口与解释；核心计算（题量、判分、统计）用确定性代码。
-   每个 Agent 的工具按上下文隔离，不建全局工具大杂烩。

#### 8.5.2 各 Agent 职责摘要

|                |                              |                                  |
|----------------|------------------------------|----------------------------------|
| Agent          | 核心能力                     | 确定性/LLM 分工                  |
| 营销 Agent     | 内容生成、话术、线索跟进     | LLM 生成，规则约束投放           |
| 助教 Agent     | 答疑、引导式教学             | LLM 为主，知识库检索辅助         |
| 出题 Agent     | 按视频/知识点出题、组卷      | 截取与题量确定性，题目生成用 LLM |
| 自主练习 Agent | 会话管理、准入校验、合并题目 | 流程确定性，入口用 LLM           |
| 批改 Agent     | 逐题批改、反馈               | rubric 确定性校验 + LLM 评分解释 |
| 学情分析 Agent | 画像、趋势、归因             | 统计确定性，归因解释用 LLM       |

### 8.6 后台管理模块（管理端）

面向管理人员、教师/教研、销售人员，与学员端（对话页/自主练习页/学情看板）分离的独立管理端。分三期交付：第一期补齐课程/题目/线索 CRUD 与会话查看（即项目规划中的后台加分项）；第二期补知识库运维（课件/FAQ 切块向量化的一键触发，替代手动 CLI）；第三期补监控与配置中心。

#### 8.6.1 第一期：运营基础（鉴权 + 课程/题目/线索 CRUD + 会话查看）

##### 8.6.1.1 FR-025 管理端登录与鉴权

-   **功能描述**：管理员、教师/教研、销售人员三类角色登录管理端，按角色控制可见菜单与可执行操作。
-   **输入**：账号、密码（或已有系统单点登录票据）。
-   **输出**：JWT（含角色声明）+ 权限范围内的菜单与操作。
-   **业务规则**：管理员可访问全部模块；教师/教研可访问课程、题目、知识库、学情；销售人员可访问线索与售前会话；未授权操作返回 403。

##### 8.6.1.2 FR-026 课程管理

-   **功能描述**：课程/章节/视频的列表查询与编辑，支持在线维护课件内容。
-   **输入**：筛选条件（方向/岗位/关键词）、编辑内容（章节 content_md、视频信息等）。
-   **输出**：课程/章节/视频列表与详情、编辑保存结果。
-   **业务规则**：数据来自同步缓存表 course/chapter/video；编辑写入本系统 MySQL，不直接改动已有系统数据源。

##### 8.6.1.3 FR-027 题目管理

-   **功能描述**：练习题目的列表、详情查看与状态管理（上架/下架）。
-   **输入**：筛选条件（视频/题型/状态）、状态变更。
-   **输出**：题目列表与详情、状态变更结果。
-   **业务规则**：数据来自 practice_question；下架不影响历史练习记录。

##### 8.6.1.4 FR-028 线索管理

-   **功能描述**：销售线索的列表、筛选、详情查看与跟进状态更新。
-   **输入**：筛选条件（方向/来源/是否已报 VIP）、跟进状态与备注。
-   **输出**：线索列表与详情、跟进状态更新结果。
-   **业务规则**：数据来自 lead；联系电话按 §12.3 脱敏展示。

##### 8.6.1.5 FR-029 会话记录查看

-   **功能描述**：客服与答疑会话记录的查询与详情查看，用于运营抽检 AI 回答质量。
-   **输入**：筛选条件（来源 sales/teaching、学员、时间）。
-   **输出**：会话列表（按 conversationId 归组）与会话详情（问题/回答/溯源）。
-   **业务规则**：数据来自 conversation_message，按 source 区分客服/助教来源。

#### 8.6.2 第二期：知识库与内容运维

##### 8.6.2.1 FR-030 课件文档管理

-   **功能描述**：课件 Markdown 文档的上传、替换、删除与章节结构预览。
-   **输入**：课件 md 文件（data/docs/*.md）。
-   **输出**：文档列表与章节结构预览、上传/替换/删除结果。
-   **业务规则**：文档为助教 RAG 与视频内容复制的数据源；替换/删除后需触发重新切块向量化（FR-031）。

##### 8.6.2.2 FR-031 一键切块与向量化

-   **功能描述**：触发课件重新切块并重建向量库，替代手动 CLI。
-   **输入**：触发指令（全量或指定文档）。
-   **输出**：异步任务进度与结果（切块数、入库数、耗时）。
-   **业务规则**：执行 build_chunks → build_knowledge_base 管线，重建集合 teaching_assistant_chunks；失败可重试并记录日志。

##### 8.6.2.3 FR-032 FAQ 知识库管理

-   **功能描述**：售前 FAQ 内容的编辑与向量库重建，以及向量库状态查看。
-   **输入**：FAQ 内容（faq.md）、重建指令。
-   **输出**：FAQ 编辑结果、sales_faq 重建结果、集合状态（chunk 数、最近构建时间）。
-   **业务规则**：FAQ 为售前 RAG 数据源；重建后即时生效。

#### 8.6.3 第三期：监控与配置

##### 8.6.3.1 FR-033 学情与练习看板

-   **功能描述**：教师/管理人员视角的学情与练习数据查看。
-   **输入**：学员/班级筛选条件。
-   **输出**：多学员学情对比、练习记录与作答明细。
-   **业务规则**：复用学情分析接口（analytics）与练习表（practice_session/practice_answer），只读。

##### 8.6.3.2 FR-034 系统配置中心

-   **功能描述**：LLM/Embedding 模型、检索阈值、top_k 等运行参数的可视化配置。
-   **输入**：配置项与取值。
-   **输出**：配置保存结果与生效状态。
-   **业务规则**：敏感配置（密钥）加密存储；改动记录审计日志。

##### 8.6.3.3 FR-035 系统监控

-   **功能描述**：健康检查、token 用量、同步任务状态、知识库构建任务日志的查看。
-   **输入**：时间范围/任务筛选。
-   **输出**：监控指标与任务日志。
-   **业务规则**：对接 /health 与可观测日志；异常仅展示，不自动告警。

## 9. 业务规则

### 9.1 核心业务规则

#### 9.1.1 智能客服规则

-   对模糊意向主动追问澄清；课程分类需引导到二级分类（一级 → 二级）。
-   课程分类树与课程列表来自已有课程系统接口，实时查询（分类树缓存）。
-   无匹配课程时如实告知（不编造），并引导留资。
-   多轮对话中记住已选择的一级/二级分类；留资挂接 VIP 报到流程。

#### 9.1.2 答疑规则

-   基于课程视频/课件 RAG 检索回答。
-   每次答疑记录会话（问题与回答落库）。

#### 9.1.3 自主练习规则

-   学生选择课程下的知识点（视频）区间，前端按所选视频累计时长校验，要求
    45–120 分钟；后端不校验时长。
-   题量按切片内容总长度映射：10~15 道不定项 + 3~5 道论述 + 1 道场景；
    代码填空仅当切片含 ≥15 行 \`\`\` 代码块时出 1 道。
-   每次发起练习均重新生成题目，不复用。
-   不定项选择/代码填空确定性判分；论述/场景题调批改 Agent。
-   出题截取、题量计算、判分统计用确定性代码；LLM 只做生成与解释。

### 9.2 默认处理规则

当用户输入信息不足：

系统应该：

-   请求补充信息（多轮追问澄清方向与基础）；
-   返回默认结果；
-   给出提示。

### 9.3 数据不足规则

当系统无法获得有效信息：

系统：

-   不允许编造结果（无匹配课程、无课件依据时如实告知）；
-   明确提示信息不足；
-   必要时引导用户补充信息。

## 10. 系统处理流程

### 10.1 普通业务流程

    用户提交请求
         ↓
    系统理解请求
         ↓
    判断业务类型
         ↓
    获取相关数据
         ↓
    处理业务逻辑
         ↓
    生成结果
         ↓
    返回用户

### 10.2 自主练习主流程

    学生进入自主练习
      → 选择已购课程，展示该课程下的知识点（视频）列表
      → 学生勾选若干视频（区间连续）
      → 前端校验：所选视频累计时长在 45–120 分钟？
           否 → 提示，不允许开始
           是 → 进入答题页
      → 前端提交所选视频内容（courseDocument + videos[].videoId）
      → 后端直读视频内容 → 清洗 Markdown → 计算题量 → 调出题 Agent 出题 → 入库
      → 生成 practiceId，返回一套题（按题型分组）
      → 学生逐题作答并提交（自然作答格式）
      → 后端判分：不定项选择/代码填空确定性判分；论述/场景调批改 Agent
      → 回填 PracticeAnswer，返回得分与逐题结果

### 10.3 前置流程：课件与视频准备（离线）

1.  课件 PDF 批量转 Markdown，存入 Chapter.contentMd（保留标题 \#
    与代码块 \`\`\`）。
2.  视频上传时 ffprobe 获取 durationSeconds，写入视频元数据。
3.  教研人工复制每个视频讲解对应的课件文档片段，存入 Video.contentMd。
4.  学生观看视频，完成记录写入 StudentVideoProgress。

## 11. 异常处理需求

### 11.1 外部服务异常

当：第三方服务（LLM 服务等）不可用。

系统：

-   尝试备用方案（重试一次）；
-   返回降级结果；
-   提示用户。

### 11.2 数据查询失败

系统：

-   视频内容缺失时提示教研补录；
-   无结果时明确说明（不编造，提示人工复核）。

### 11.3 系统异常

要求：

-   隐藏内部错误；
-   返回用户可理解提示。

### 11.4 异常场景处理清单

|                      |                                                    |
|----------------------|----------------------------------------------------|
| 场景                 | 处理                                               |
| 视频内容缺失         | 该视频不出题，提示教研补录内容                      |
| 视频内容超长         | 按段落二次切分或先摘要                             |
| 选中视频无代码块     | 静默跳过代码题，不提示                             |
| 某视频出题失败       | 其他视频正常返回，失败视频提示重试或从其他视频补题 |
| 累计时长不在 45–120 分钟 | 前端拦截并提示已选时长与差额                           |
| 学生未学完视频       | 不出现在可选列表                                   |
| LLM 输出不符合 JSON  | 重试一次，仍失败则该题丢弃并记录日志               |
| 批改异常             | 标记异常转人工，不阻塞其他题                       |

## 13. 非功能需求

### 13.1 性能需求

系统应：

-   支持多视频并行出题；
-   单视频超时不影响其他视频；
-   保证响应速度；
-   避免重复计算（题目复用避免重复调用模型）。

### 13.2 可用性需求

系统：

-   单点故障不能导致整体不可用；
-   支持异常恢复（批改异常不阻塞其他题、单视频失败不影响整体）。

### 13.3 可维护性需求

系统支持：

-   功能扩展；
-   模块升级；
-   数据更新；
-   题型 prompt 与题量映射规则可配置，不硬编码。

### 13.4 可扩展性需求

未来支持：

-   新业务（第二梯队 Agent）；
-   新数据；
-   新接口；
-   按负载与团队规模拆分微服务。

### 13.5 易用性需求

要求：

-   操作简单；
-   无需学习复杂规则；
-   输出易理解；
-   代码题自动判断（而非用户选择）降低交互复杂度。

### 13.6 其他非功能约束

-   **成本**：题目复用避免重复调用模型；代码题仅在存在代码块时生成。
-   **可追溯**：题目保留 videoId 与来源 practiceId，支持溯源与质量排查。
-   **数据一致性**：出题成功后批量插入题目；提交后批量插入作答。
-   **架构约束**：context 间禁止直接依赖，shared 不依赖 context，用
    ArchUnit 守住。

## 16. 业务边界

明确：

系统可以：

-   提供课程信息查询与 7×24 在线咨询；

## 附录 B. 关键设计决策记录

1.  **限界上下文划分 Agent
    边界**：每个业务领域独立上下文，共享基础设施仅放纯技术能力。
2.  **按视频出题而非按章节**：解决整章上下文过长、注意力稀释问题。
3.  **内容快照而非锚点截取**：视频直接存储其讲解对应的课件文档片段，出题直读，免去运行时锚点定位与截取。
4.  **PDF 转 Markdown 存储**：保留标题与代码块结构，供视频内容复制与助教溯源使用。
5.  **代码题自动判断而非用户选择**：降低交互复杂度，编程课场景保留代码题价值。
6.  **每次重新出题**：自主练习不复用历史题目，保证题目新鲜度，不引入题库复杂度。
7.  **多视频合并为一套题**：前端体验统一，后台按 videoId
    分组支撑批改与学情定位。
8.  **确定性代码兜底 LLM**：出题截取、题量计算、判分统计用代码；LLM
    只做生成与解释。
9.  **模块化单体起步**：不提前拆微服务，按负载与团队规模演进。
